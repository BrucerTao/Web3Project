## 项目概述

**Monad Agentic Payment** 是一个为 AI Agent 设计的原生安全支付系统，构建在 Monad 链上。

### 核心设计理念

| 设计原则 | 说明 |
|----------|------|
| **非托管** | 用户始终持有主私钥，Agent 仅使用受限的 Session Key |
| **策略驱动** | 所有支付必须通过策略引擎验证 |
| **可审计** | 每笔支付都有完整的决策记录和链上凭证 |
| **Agent 原生** | 为 AI Agent 自动化场景设计，而非人工操作 |

## 能力展示控制台（Web UI）

面向演示与产品化展示的一层 **浏览器控制台**（内部代号 **Agentic Treasury Console**）：在单进程内启动内存态 `AgenticWallet`，通过 **HTTP 静态页 + JSON API** 将策略限额、模拟支付、人机门闩（人工审批）与审计流水可视化，与 CLI / MCP / SDK 使用同一套核心逻辑，不引入额外业务分支。

### 定位与能力边界

| 维度 | 说明 |
|------|------|
| **目标** | 展示 Agent 支付在「策略 → 执行/拦截 → 审计」全链路上的行为 |
| **技术形态** | Node 内置 `http` 提供 `web/` 下静态文件；业务通过 REST 调用 `AgenticWallet` |
| **数据持久化** | 审计日志保存到 `data/<钱包地址>/audit-logs.json`，重启后可恢复历史记录 |
| **数据隔离** | 不同钱包地址的数据完全隔离，不会互相干扰 |
| **构建** | 前端无打包步骤，修改 `web/*` 后刷新浏览器即可 |

### 页面模块（与后端能力对应）

- **策略与限额**：编辑 `maxSinglePayment`、`dailyBudget`、`weeklyBudget`、`requireHumanAbove`（单位 USD，与 `Policy` / `PolicyEngine` 一致），提交后调用 `updatePolicy`。
- **运行时上下文**：展示当前演示用钱包地址、Agent ID、Session ID、Policy ID，便于对照审计与链上浏览器。
- **模拟 Agent 支付**：表单提交收款地址、金额（ETH）、事由，服务端调用 `requestPayment`；策略引擎按内置 ETH→USD 近似换算判断是否触发 **人工确认**。
- **人机门闩 · 待确认**：列出需审批的审计项；**批准** 调用 `approvePayment(auditLogId, true)`，**拒绝** 调用 `approvePayment(auditLogId, false)` 并更新审计状态。
- **审计流水**：展示 `getAuditLogs` 结果表格；支持手动同步与可选定时刷新；汇总行来自 `getStats`。
  - 显示字段：时间、交易 ID、风险等级、金额 (ETH)、金额 (USD)、收款地址、**发款地址**、状态、需人工审批
  - 地址截断显示，鼠标悬停时显示完整地址

### 服务端入口与静态资源

- **入口**：`src/ui-server.ts`（`npm run ui`）。
- **监听**：默认 `127.0.0.1:3847`，环境变量 `UI_PORT` 指定首选端口；若端口被占用，会自动递增尝试最多 30 个端口并打印提示。
- **静态路径**：根路径返回 `web/index.html`，`/styles.css`、`/app.js` 同源加载。

### HTTP API 一览

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/init` | 初始化钱包（传入私钥或生成随机钱包） |
| `GET` | `/api/initialized` | 检查是否已初始化 |
| `GET` | `/api/state` | 链配置、钱包地址、Session/Agent/Policy 与当前策略摘要 |
| `PATCH` | `/api/policy` | JSON body 更新策略限额字段 |
| `POST` | `/api/payment` | `recipient`、`amountEth`、`reason`（及可选 `taskId`）→ `requestPayment` |
| `GET` | `/api/pending` | 待人工审批的审计项 |
| `POST` | `/api/approve` | `{ auditLogId, approved }` → 批准或拒绝 |
| `GET` | `/api/audit?limit=` | 审计列表 |
| `GET` | `/api/stats` | 钱包统计 |

### 环境变量

| 变量 | 作用 |
|------|------|
| `PRIVATE_KEY` | 可选；若设置则使用真实钱包，否则每次启动生成随机钱包（与 `demo` 一致，仅本地演示） |
| `UI_PORT` | 可选；首选监听端口，默认 `3847` |
| `TEST_RPC_URL` | 可选；指定 RPC 地址，默认使用 Monad 测试网 `https://testnet-rpc.monad.xyz` |

### 部署说明（简要）

- **进程**：生产形态下可用 `node dist/ui-server.js`（需先 `npm run build` 且保证 `web/` 与 `dist` 相对路径仍正确，当前脚本以 `tsx` 直接运行 `src/ui-server.ts`）、`pm2`、`systemd` 等常驻；前面可挂 Nginx/Caddy 做 TLS 与反代。

### 2. Policy Engine (`src/policy-engine.ts`)

**作用**：策略验证引擎，所有支付请求必须通过此模块验证

#### 核心方法

```typescript
class PolicyEngine {
  // 添加策略
  addPolicy(policy: Policy): void

  // 获取策略
  getPolicy(policyId: string): Policy | undefined

  // 列出所有策略
  listPolicies(): Policy[]

  // 检查支付请求（核心方法）
  async checkPayment(
    request: PaymentRequest,
    policy: Policy,
    sessionKey?: SessionKey
  ): Promise<PolicyCheckResult>

  // 记录支出（用于每日预算跟踪）
  recordSpend(policyId: string, amountUSD: number): void

  // 创建默认策略
  static createDefaultPolicy(agentId: string): Policy
}
```

          ▼

## 常见问题

### Q: 如何重置每日预算？

A: 每日预算会自动在每天 0 点重置（基于 `dailySpent` Map 的日期键）。

### Q: Session Key 过期了怎么办？

A: 过期后会自动标记为 `isActive: false`。创建新的 Session Key 即可：

```typescript
const newSessionKey = sessionKeyManager.createSessionKey(
  agentId,
  userId,
  policyId,
  { ttlHours: 24 }
);
```

### Q: 如何查看某笔支付的完整决策过程？

A: 使用 `generateReceipt` 生成收据：

```typescript
const receipt = agenticWallet.generateReceipt(auditLogId);
console.log(receipt);
```

### Q: 如何配置白名单？

A: 在注册 Agent 时指定：

```typescript
agenticWallet.registerAgent('Agent', {
  policy: {
    allowedRecipients: [
      '0x123...',  // 只允许支付给这些地址
      '0x456...'
    ]
  }
});
```

### Q: MCP Server 无法启动？

A: 检查以下几点：
1. 确保 Ganache 在运行（如果使用本地测试）
2. 确认 `.env` 文件中设置了 `TEST_PRIVATE_KEY` 或 `PRIVATE_KEY`
3. 检查 `cwd` 配置是否指向正确的项目目录

## 安全注意事项

1. **私钥安全**
   - 永远不要将私钥提交到 Git
   - 使用 `.env` 文件存储，确保在 `.gitignore` 中
   - 生产环境使用硬件钱包或密钥管理服务

2. **策略配置**
   - 始终设置合理的额度限制
   - 对不可信 Agent 使用白名单
   - 定期审查审计日志

3. **Session Key**
   - 设置合理的过期时间
   - 不再使用时立即撤销
   - 监控使用统计
