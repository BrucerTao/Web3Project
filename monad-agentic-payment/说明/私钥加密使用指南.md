# 私钥加密功能使用指南

## 概述

本系统支持使用 **AES-256-CBC + PBKDF2** 加密算法保护钱包私钥，避免私钥以明文形式存储在 `.env` 文件中。

## 安全特性

- **AES-256-CBC**: 军事级对称加密标准
- **PBKDF2-SHA256**: 密钥派生算法，100,000 次迭代抗暴力破解
- **随机 Salt**: 每次加密生成唯一 salt，防止彩虹表攻击
- **随机 IV**: 每次加密生成唯一初始化向量，确保相同私钥加密结果不同

### 步骤 1: 加密私钥

运行加密 CLI 工具：

```bash
cd monad-agentic-payment

```

```
设置保护密码 (用于解密私钥):
密码：********
确认密码：********

✅ 加密成功！

────────────────────────────────────────────────────────────
将以下内容添加到 .env 文件:

ENCRYPTED_PRIVATE_KEY={"ciphertext":"U2FsdGVkX1+5vK8...","salt":"abc123...","iv":"def456..."}
────────────────────────────────────────────────────────────

📝 使用说明:
1. 复制上面的 ENCRYPTED_PRIVATE_KEY=... 到 .env 文件
2. 启动 MCP 或 UI 服务时会自动提示输入密码解锁
3. 私钥明文不会存储在磁盘上，仅保存在内存中
```

### 步骤 2: 更新 .env 文件

编辑 `.env` 文件，添加加密后的私钥：

```bash

# 添加加密私钥
```

## 技术细节

### 加密算法流程

```
用户密码 + 随机 Salt
       ↓
   PBKDF2-SHA256 (100,000 次迭代)
       ↓
   AES-256 密钥 (32 字节)
       ↓
   AES-256-CBC 加密私钥
       ↓
   Base64 编码输出
```

### 加密数据结构

```json
{
  "ciphertext": "Base64 编码的密文",
  "salt": "Base64 编码的 salt (16 字节)",
  "iv": "Base64 编码的 IV (16 字节)"
}
```

### 安全强度

| 组件 | 强度 | 说明 |
|------|------|------|
| AES-256 | 2^256 | 军事级加密，经典计算机无法破解 |
| PBKDF2 | 100,000 次迭代 | 暴力破解单个密码约需 1 秒 |
| Salt | 128 位随机 | 防止彩虹表攻击 |
| IV | 128 位随机 | 确保相同明文加密结果不同 |

## 最佳实践

### ✅ 推荐做法

1. **使用强密码**: 至少 8 位，包含大小写字母、数字、特殊字符
2. **密码管理**: 使用密码管理器（如 1Password、Bitwarden）存储密码
3. **环境隔离**: 生产环境使用独立的加密私钥
4. **定期轮换**: 定期更换私钥和密码

### ❌ 避免做法

1. 不要在代码中硬编码密码
2. 不要将密码提交到 Git
3. 不要使用弱密码（如 `123456`、`password`）
4. 不要在不安全的环境中输入密码

## 常见问题

### Q1: 忘记密码怎么办？

**A**: 私钥无法恢复。请：
1. 使用备份的私钥重新加密
2. 或转移资产到新钱包，重新生成私钥

### Q2: 加密后的私钥可以安全存储在哪里？

**A**: 可以存储在：
- ✅ 代码仓库（`.env` 文件已加入 `.gitignore`）
- ✅ 数据库
- ✅ 云存储（如 AWS S3、Google Drive）

但仍建议限制访问权限。

### Q3: 可以在 CI/CD 中使用加密私钥吗？

**A**: 可以。在 CI/CD 流程中：
1. 将加密私钥存入环境变量
2. 将密码存入秘密管理（如 GitHub Secrets）
3. 运行时自动解密

### Q4: 加密会影响性能吗？

**A**: 影响可忽略：
- 解密过程仅需几毫秒
- 仅在服务启动时执行一次
- 运行时不影响交易签名性能

## 迁移指南

### 从明文迁移到加密

1. 运行 `npx tsx src/cli-encrypt.ts` 加密当前私钥
2. 将输出的 `ENCRYPTED_PRIVATE_KEY` 添加到 `.env`
3. 注释掉或删除 `.env` 中的 `PRIVATE_KEY`
4. 重启服务，验证密码解锁正常

### 回退到明文

1. 在 `.env` 中恢复 `PRIVATE_KEY`
2. 删除或注释掉 `ENCRYPTED_PRIVATE_KEY`
3. 重启服务

## 注意事项

### 1. MCP 配置格式

在 `.mcp.json` 中配置加密私钥时，**必须进行 JSON 转义**：

```json
// ❌ 错误 - 双引号嵌套导致 JSON 解析失败
{
  "ENCRYPTED_PRIVATE_KEY": "{"ciphertext":"...","salt":"..."}"
}

// ✅ 正确 - 内层双引号用反斜杠转义
{
  "ENCRYPTED_PRIVATE_KEY": "{\"ciphertext\":\"...\",\"salt\":\"...\",\"iv\":\"...\"}"
}
```

**完整示例** (`/Users/huangtao/mybiz/Web3Project/.mcp.json`)：

```json
{
  "mcpServers": {
    "agentic-wallet": {
      "command": "npx",
      "args": [
        "tsx",
        "monad-agentic-payment/src/mcp-server.ts"
      ],
      "env": {
        "TEST_RPC_URL": "http://127.0.0.1:8545",
        "ENCRYPTED_PRIVATE_KEY": "{\"ciphertext\":\"...\",\"salt\":\"...\",\"iv\":\"...\"}",
        "DECRYPT_PASSWORD": "你的密码"
      }
    }
  }
}
```

### 2. 快速生成 MCP 配置（推荐）

**最简单的方式**：使用专用命令直接生成可用的配置：

```bash
npm run encrypt:mcp
```

**或者使用基础命令 + 参数**：
```bash
npm run encrypt -- --mcp
```

> 💡 **说明**：`--` 是分隔符，表示后面的参数要传递给脚本。`npm run script -- args` 是 npm 传递参数给子脚本的标准方式。
> 
> 类似场景：`node app.js --port 3000` 中的 `--port 3000` 就是传给 `app.js` 的参数。

输出示例（已自动转义，可直接使用）：
```json
{
  "mcpServers": {
    "agentic-wallet": {
      "command": "npx",
      "args": ["tsx", "monad-agentic-payment/src/mcp-server.ts"],
      "env": {
        "TEST_RPC_URL": "http://127.0.0.1:8545",
        "ENCRYPTED_PRIVATE_KEY": "{\"ciphertext\":\"...\",\"salt\":\"...\",\"iv\":\"...\"}",
        "DECRYPT_PASSWORD": "你的密码"
      }
    }
  }
}
```

**直接复制整个输出保存为 `.mcp.json` 即可**，无需手动转义！

### 3. 手动转义方法

如果你已经有加密输出，需要手动转义，可以使用 Node.js：

```bash
# 假设你有加密后的 JSON 字符串（未转义）
ENCRYPTED='{"ciphertext":"PMIWefTcfvJ9qkD0nQZNKkuRINvMk1wCG/i+/JqVwJYu7XaLjst1XbrkizO6MddclMpvjqccvtPKWjshsPCeYC0xKU6/3vmbKxcgl4fcYPM=","salt":"SdPMoRfZgdcz/gCusvXBWw==","iv":"VPtLex5iDcNWM8eCDaspLA=="}'

# 使用 Node.js 进行 JSON 转义
node -e "console.log(JSON.stringify($ENCRYPTED))"

# 输出转义后的字符串，复制到 .mcp.json 中
```

或者使用 `jq` 工具：

```bash
# 使用 jq 转义
echo "$ENCRYPTED" | jq -R .

# 或使用 jq 生成完整配置
jq -n \
  --arg encrypted "$ENCRYPTED" \
  --arg password "你的密码" \
  '{
    mcpServers: {
      "agentic-wallet": {
        command: "npx",
        args: ["tsx", "monad-agentic-payment/src/mcp-server.ts"],
        env: {
          TEST_RPC_URL: "http://127.0.0.1:8545",
          ENCRYPTED_PRIVATE_KEY: $encrypted,
          DECRYPT_PASSWORD: $password
        }
      }
    }
  }'
```

### 6. 自动解密模式

MCP 模式下无法交互式输入密码，需要设置 `DECRYPT_PASSWORD` 环境变量：

```json
{
  "env": {
    "ENCRYPTED_PRIVATE_KEY": "...",
    "DECRYPT_PASSWORD": "你的密码"  // 自动解密用
  }
}
```

⚠️ **注意**：`DECRYPT_PASSWORD` 会明文存储在配置文件中，安全性介于纯明文和交互式输入之间。

### 7. 安全性对比

| 模式 | 安全性 | 适用场景 |
|------|--------|---------|
| 交互式输入密码 | ⭐⭐⭐⭐⭐ | UI/CLI 本地开发 |
| DECRYPT_PASSWORD | ⭐⭐⭐ | MCP/CI 自动化 |
| 明文私钥 | ⭐⭐ | 仅测试环境 |

### 8. 密码管理建议

- 使用密码管理器（1Password、Bitwarden）存储密码
- 不要在 Git 中提交包含密码的文件
- 生产环境使用密钥管理服务（HashiCorp Vault、AWS Secrets Manager）
- 定期更换密码并重新加密
